# Liquid Prism 0.7

This release gives apps control over chrome placement and component composition
while keeping native glass defaults. Styles remain immutable and merge field by
field: direct arguments, local style, component theme, then native defaults.

Examples assume the app supplies its own callbacks and page widgets.

## Toolbar composition

`LiquidPrismScaffold.toolbar` accepts typed content. Consecutive action items
share a capsule; explicit groups create separate capsules. Fixed and flexible
spacers separate groups. Custom content keeps its own input and semantics.

```dart
LiquidPrismScaffold(
  title: const Text('Inbox'),
  navigationBarStyle: const GlassNavigationBarStyle(
    titleAlignment: GlassTitleAlignment.center,
  ),
  toolbar: [
    GlassToolbarItem(
      placement: GlassToolbarPlacement.topTrailing,
      label: 'Done',
      onPressed: save,
    ),
    GlassToolbarGroup(
      placement: GlassToolbarPlacement.bottomLeading,
      items: [
        GlassToolbarItem(label: 'Undo', icon: const Icon(CupertinoIcons.arrow_uturn_left), onPressed: undo),
        GlassToolbarItem(label: 'Redo', icon: const Icon(CupertinoIcons.arrow_uturn_right), onPressed: redo),
      ],
    ),
    GlassToolbarItem.custom(
      placement: GlassToolbarPlacement.principal,
      width: 160,
      child: const Text('Editing'),
    ),
  ],
  body: const Editor(),
)
```

Placements are `automatic`, `topLeading`, `topTrailing`, `principal`,
`bottomLeading`, `bottom` and `bottomTrailing`. Principal content replaces the
inline title. The large title remains independent. Native menus continue to use
`GlassToolbarItem.menu` and the iOS menu bridge.

Standalone `LiquidPrismToolbar(content: [...])` uses the same models. Item
placements belong to the scaffold; standalone toolbars use declaration order. In a sliver app bar, bottom placements
form a pinned row below the accessory.
`GlassToolbarSpacer.fixed(12)` creates a fixed gap and
`GlassToolbarSpacer.flexible()` uses the available space. Custom items render
without an added gesture owner; placing them inside an explicit group gives
them a shared glass background.

## Navigation titles and scroll behavior

Both app bars accept interactive title widgets. Inline and expanded titles have
independent alignment; the inactive representation leaves focus and semantics.
Inline titles now center by default, with Cupertino system typography. Use
`titleAlignment: GlassTitleAlignment.leading` for the earlier leading layout.
Standard top-bar content clearance now matches the measured native 10 points;
`contentSpacing` overrides it.

```dart
navigationBarStyle: const GlassNavigationBarStyle(
  titleAlignment: GlassTitleAlignment.center,
  largeTitleAlignment: GlassTitleAlignment.leading,
  minimizationBehavior: GlassToolbarMinimizationBehavior.onScrollDown,
  minimizationRestoration: GlassToolbarMinimizationRestoration.automatic,
),
```

`automatic`/`never` keep controls pinned. `onScrollDown` hides the title and controls
together and reveals them on reversal; `onScrollUp` reverses that behavior.
`atScrollEdge` restoration waits for the content's top. The safe-area adjustment
can be disabled. Top-docked tabs move with the navigation chrome.

Large-to-inline collapse uses a measured 200 ms ease-in-out large-title fade and
separate fitted inline reveal/hide springs. Apps can override those timings with
`largeTitleFadeDuration`, `largeTitleFadeCurve`, `revealSpring`, `hideSpring`
and `inlineTitleDelay`. The default 12 ms inline onset lag is fitted from the
shared native timeline; it applies only when starting at rest.
Reduce Motion swaps immediately; interrupted inline springs retain velocity.
[Native measurements](../navigation_bar_spec.json) distinguish captured values
from renderer fits and document the remaining overscroll difference.

## Buttons

A text action needs only its label and callback:

```dart
LiquidPrismButton(label: 'Save', onPressed: save)

LiquidPrismButton(
  label: 'Upload',
  icon: const Icon(CupertinoIcons.cloud_upload),
  onPressed: upload,
  variant: GlassButtonVariant.prominent,
  style: const GlassButtonStyle(
    size: GlassControlSize.large,
    sizing: GlassButtonSizing.fill,
    labelPlacement: GlassLabelPlacement.below,
    spacing: 6,
  ),
)
```

A supplied `child` replaces the generated label/icon content. Icon-only and
native menu constructors remain available. Labels, alignment, minimum/maximum
constraints, padding and typography can be configured without replacing input
handling. Null callbacks disable every activation path.

## Navigation and tabs

`GlassNavigationBarStyle` exposes title alignment, control-row height, content
padding and expanded-title extent. Automatic alignment and native row dimensions
remain the defaults. Directional values follow RTL.

`GlassScaffoldStyle` controls tab/bottom-bar margins, alignment and maximum width.
`GlassTabBarPlacement` can explicitly dock at the bottom, top, leading or trailing
edge; automatic placement still follows native system chrome and sidebar mode
remains available. Keyboard avoidance and body safe-area insets follow the chosen
dock. Compact tabs remain the default; `GlassTabBarSizing.fill` is opt-in.

Try the interactive example with:

```sh
cd example
flutter run -t lib/composition_main.dart -d <device-id>
```

## Migration

| 0.6 | 0.7 |
| --- | --- |
| `actions: [item, [other]]` | `toolbar: [item, GlassToolbarGroup(items: [other])]` |
| `LiquidPrismToolbar(groups: [[item]])` | `LiquidPrismToolbar(content: [GlassToolbarGroup(items: [item])])` |
| `GlassButtonAppearance` | `GlassButtonStyle` |
| `GlassButtonStyle.glass` / `.glassProminent` | `GlassButtonVariant.regular` / `.prominent` |
| Button `buttonStyle:` | `variant:` |
| Tab style `expanded: true` | `sizing: GlassTabBarSizing.fill` |
| Search `appearance:` / text `style:` | Component `style:` / `textStyle:` |
| Navigation `revealCurve` | `revealSpring` (incoming), `hideSpring` (outgoing) |
| `GlassNavigationBarStyle.largeTitleSpring` | `largeTitleFadeDuration` and `largeTitleFadeCurve` |

Replaced APIs are removed. Button variant/size/padding, toolbar size/item width
and search cancel/inset fields are nullable so omission inherits the style;
native defaults remain the fallback; navigation title motion, font selection,
centering and standard content clearance are corrected from native measurements. Controller ownership, parent-owned values, cancellation,
RTL, Reduce Motion, native popup presentation and shader role IDs retain their
contracts. The switch, slider and segmented-control geometry and lens styles
remain independently configurable through their existing typed styles.

## References

Apple distinguishes semantic and positional placements in
[ToolbarItemPlacement](https://developer.apple.com/documentation/swiftui/toolbaritemplacement).
[ToolbarSpacer](https://developer.apple.com/documentation/swiftui/toolbarspacer)
provides fixed and flexible breaks. These APIs inform the composition model;
Liquid Prism exposes it through Flutter constructors and immutable styles.
